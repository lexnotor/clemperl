# T4, paiement : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** un vendeur déclare comment il accepte d'être payé, l'acheteur choisit une méthode
par boutique, et ce qui se règle en ligne passe par un adapter, une redirection et un webhook
signé.

**Architecture:** l'argent est un axe SÉPARÉ de l'expédition. `Order.status` ne bouge pas ;
une colonne `paymentStatus` porte le statut normalisé, et une table `payments` porte la trace,
une ligne par tentative, avec le payload brut du fournisseur chiffré. Tout le code qui touche
un fournisseur ou déplace l'axe de l'argent vit dans `apps/api`, appelé depuis le navigateur ;
les fronts continuent de LIRE la base.

**Tech Stack:** NestJS 12, Next.js 16 (App Router, server actions), Prisma 7, PostgreSQL,
`node:crypto` (AES-256-GCM, HMAC-SHA256), next-intl, Tailwind 4, Vitest, Jest + Testcontainers,
Playwright.

**Spec:** `docs/superpowers/specs/2026-10-11-t4-paiement-design.md`

## Review Focus

Cinq classes d'entrée que la spec implique et qu'aucune tâche n'exercerait d'elle-même. Chaque
ligne a son test, posé dans la tâche qui possède le code.

1. **Un webhook signé correctement mais dont le `providerRef` est inconnu.** Réponse `404`,
   aucune écriture, aucune tentative créée. Un paiement dont la plateforme n'a aucune trace de
   démarrage n'est pas le sien. Testé en tâche 6.
2. **Un webhook dont le corps est du JSON valide mais aux champs absents ou mal typés**
   (`providerRef` absent, `status` inconnu, corps tronqué). `interpret` rend `null`, réponse
   `400`, aucune écriture. Testé en tâche 5 et en tâche 6.
3. **Un payload chiffré altéré d'un seul octet.** Le déchiffrement LÈVE au lieu de rendre des
   octets qui ressemblent à du JSON. Testé en tâche 5.
4. **Une méthode soumise au formulaire que la boutique n'accepte pas**, ou qui n'est pas une
   valeur de l'enum (champ bricolé dans le navigateur). Refus nommé, aucune commande écrite,
   et le panier intact. Testé en tâche 4.
5. **`/payments/start` sur une commande annulée, déjà réglée, ou appartenant à quelqu'un
   d'autre.** Refus, aucune tentative créée. Testé en tâche 6.

- [ ] **Step 2: Ajouter la colonne du vendeur**

Dans `model Vendor`, juste après `categories` :

```prisma
  // donc une table de jointure dont toutes les colonnes sauf deux seraient vides mentirait
  // sur ce qu'elle porte. Une liste vide sort la boutique du catalogue.
  paymentMethods E_PAYMENT_METHOD[] @map("payment_methods")
```

- [ ] **Step 3: Ajouter les deux colonnes de la commande et sa relation**

Dans `model Order`, après `currency` :

```prisma

  // à une commande ce que le vendeur accepte aujourd'hui, pas ce qui a été choisi.
  paymentMethod E_PAYMENT_METHOD @map("payment_method")

  // Le statut NORMALISÉ, seule chose que le domaine connaît de l'argent. Il ne contraint
  // pas `status`, qui dit où en est l'expédition : les deux axes sont indépendants.
  paymentStatus E_PAYMENT_STATUS @default(PENDING) @map("payment_status")
```

Puis dans les relations du même modèle, après `items` :

```prisma
  payments OrderPayment[]
```

Et dans les index, après `@@index([buyerId, createdAt])` :

```prisma
  @@index([vendorId, paymentStatus])
```

- [ ] **Step 4: Déclarer le modèle des tentatives**

Le modèle s'appelle `OrderPayment` et sa table `payments`. `Payment` seul serait ambigu le
jour où T5 facturera des abonnements, qui sont des paiements de la plateforme et non d'une
commande.

```prisma
model OrderPayment {
  id       String           @id @default(cuid(2))
  orderId  String           @map("order_id")
  method   E_PAYMENT_METHOD
  status   E_PAYMENT_STATUS @default(PENDING)
  amount   Int
  currency E_CURRENCY

  // Nuls pour une méthode hors ligne, qui n'a aucun fournisseur. PostgreSQL traite les
  // NULL comme distincts dans un index unique, donc ces lignes ne se heurtent jamais à
  // la contrainte ci-dessous.
  provider    String?
  providerRef String? @map("provider_ref")

  // Le payload brut du fournisseur, chiffré, tel qu'il a été reçu.
  rawPayload Bytes? @map("raw_payload")

  // Qui a pointé l'encaissement, pour une méthode hors ligne. `SetNull` : supprimer un
  // compte ne doit pas emporter la preuve d'un encaissement.
  settledById String?   @map("settled_by_id")
  settledAt   DateTime? @map("settled_at")

  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  order     Order @relation(fields: [orderId], references: [id], onDelete: Cascade)
  settledBy User? @relation(fields: [settledById], references: [id], onDelete: SetNull)

  // Ce qui rend le webhook idempotent. Un fournisseur rejoue ses webhooks : c'est le cas
  // normal, pas l'exception. Sans cette contrainte un rejeu créerait une seconde ligne,
  // et le payload de la première deviendrait introuvable.
  @@unique([provider, providerRef])
  @@index([orderId, createdAt])
  @@map("payments")
}
```

Prisma ne sait pas qu'une colonne obligatoire arrive sur une table peuplée, ni ce que les
lignes existantes doivent recevoir. Le fichier produit doit finir par ressembler à ceci, dans

```sql
CREATE TYPE "payment_method" AS ENUM ('CARD', 'MOBILE_MONEY', 'CASH_ON_DELIVERY', 'BANK_TRANSFER', 'OFF_PLATFORM');
CREATE TYPE "payment_status" AS ENUM ('PENDING', 'SETTLED', 'FAILED');

ALTER TABLE "vendors" ADD COLUMN "payment_methods" "payment_method"[] NOT NULL DEFAULT ARRAY[]::"payment_method"[];

-- Les boutiques existantes gardent leur place au catalogue. Le catalogue n'admet qu'une
-- boutique acceptant au moins une méthode : sans cette ligne, elles en sortiraient TOUTES
-- le jour du déploiement.
UPDATE "vendors" SET "payment_methods" = ARRAY['OFF_PLATFORM']::"payment_method"[];

ALTER TABLE "orders" ADD COLUMN "payment_method" "payment_method" NOT NULL DEFAULT 'OFF_PLATFORM';
ALTER TABLE "orders" ADD COLUMN "payment_status" "payment_status" NOT NULL DEFAULT 'PENDING';

-- Une commande déjà expédiée qui afficherait « paiement en attente » serait une affirmation
-- fausse sur de l'argent, et c'est le genre d'affirmation qu'on ne rattrape pas.
UPDATE "orders" SET "payment_status" = 'SETTLED' WHERE "status" = 'SHIPPED';

-- Le défaut ne sert qu'à la reprise des lignes existantes. Le garder laisserait une
-- commande naître sans méthode choisie, ce que la validation refuse à l'entrée.
ALTER TABLE "orders" ALTER COLUMN "payment_method" DROP DEFAULT;

CREATE TABLE "payments" (
    "id" TEXT NOT NULL,
    "order_id" TEXT NOT NULL,
    "method" "payment_method" NOT NULL,
    "status" "payment_status" NOT NULL DEFAULT 'PENDING',
    "amount" INTEGER NOT NULL,
    "currency" "currency" NOT NULL,
    "provider" TEXT,
    "provider_ref" TEXT,
    "raw_payload" BYTEA,
    "settled_by_id" TEXT,
    "settled_at" TIMESTAMP(3),
    "created_at" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    "updated_at" TIMESTAMP(3) NOT NULL,

    CONSTRAINT "payments_pkey" PRIMARY KEY ("id")
);

CREATE UNIQUE INDEX "payments_provider_provider_ref_key" ON "payments"("provider", "provider_ref");
CREATE INDEX "payments_order_id_created_at_idx" ON "payments"("order_id", "created_at");
CREATE INDEX "orders_vendor_id_payment_status_idx" ON "orders"("vendor_id", "payment_status");

ALTER TABLE "payments" ADD CONSTRAINT "payments_order_id_fkey" FOREIGN KEY ("order_id") REFERENCES "orders"("id") ON DELETE CASCADE ON UPDATE CASCADE;
ALTER TABLE "payments" ADD CONSTRAINT "payments_settled_by_id_fkey" FOREIGN KEY ("settled_by_id") REFERENCES "users"("id") ON DELETE SET NULL ON UPDATE CASCADE;
```

les attend lors du prochain `migrate diff`.

```ts
describe("une boutique sans méthode de paiement", () => {
    // La règle est écrite UNE fois et lue à quatre endroits. Ce test échoue le jour où
    // quelqu'un en ajoute une cinquième sans la condition, ou en retire une des quatre.
    it("quitte les quatre lectures à la fois", async () => {
        const shop = await createShopWithPublishedProduct({ methods: ["OFF_PLATFORM"] });

        await expect(listCatalog(prisma, query(shop))).resolves.toMatchObject({ total: 1 });
        await expect(
            readPublishedProduct(prisma, { shopSlug: shop.slug, productSlug: shop.productSlug }),
        ).resolves.not.toBeNull();
        await expect(readShop(prisma, shop.slug)).resolves.not.toBeNull();
        await expect(
            prisma.productVariant.findFirst({ where: eligibleVariantWhere(shop.variantId) }),
        ).resolves.not.toBeNull();

        await prisma.vendor.update({
            where: { id: shop.id },
            data: { paymentMethods: [] },
        });

        await expect(listCatalog(prisma, query(shop))).resolves.toMatchObject({ total: 0 });
        await expect(
            readPublishedProduct(prisma, { shopSlug: shop.slug, productSlug: shop.productSlug }),
        ).resolves.toBeNull();
        await expect(readShop(prisma, shop.slug)).resolves.toBeNull();
        await expect(
            prisma.productVariant.findFirst({ where: eligibleVariantWhere(shop.variantId) }),
        ).resolves.toBeNull();
    });

    // Le décompte des devises est la cinquième lecture, et celle que la revue de T2d avait
    // trouvée désalignée : il comptait des produits que la liste ne montrait pas.
    it("ne compte plus dans le décompte des devises", async () => {
        const shop = await createShopWithPublishedProduct({ methods: ["OFF_PLATFORM"] });
        const avant = await countByCurrency(prisma, {});
        await prisma.vendor.update({ where: { id: shop.id }, data: { paymentMethods: [] } });
        const apres = await countByCurrency(prisma, {});

        const compte = (rows: { currency: string; productCount: number }[]) =>
            rows.find((r) => r.currency === shop.currency)?.productCount ?? 0;
        expect(compte(apres)).toBe(compte(avant) - 1);
    });
});
```

```ts
import { createCipheriv, createDecipheriv, randomBytes } from "node:crypto";

const ALGORITHM = "aes-256-gcm";
const KEY_LENGTH = 32;
const IV_LENGTH = 12;
const TAG_LENGTH = 16;

// La clé est lue au démarrage et non à chaque appel : une clé absente doit arrêter le
// processus avec son nom, et non échouer au premier webhook, des heures plus tard.
export function readPayloadKey(raw: string | undefined): Buffer {
    const key = Buffer.from(raw ?? "", "base64");
    if (key.length !== KEY_LENGTH) {
        throw new Error(
            "PAYMENT_PAYLOAD_KEY doit valoir 32 octets encodés en base64.",
        );
    }
    return key;
}

// On stocke l'IV, le sceau, puis le chiffré. L'IV est tiré à chaque appel : le réutiliser
// en GCM livre le OU exclusif des deux clairs, et surtout la clé d'authentification, ce qui
// permet de forger un sceau valide.
//
// `authTagLength` est passé aux DEUX sens. Sans lui, `setAuthTag` accepte des sceaux plus
// courts que seize octets, donc un tampon tronqué en base passerait le déchiffrement avec
// un sceau affaibli.
export function encryptPayload(key: Buffer, clear: string): Buffer {
    const iv = randomBytes(IV_LENGTH);
    const cipher = createCipheriv(ALGORITHM, key, iv, { authTagLength: TAG_LENGTH });
    const body = Buffer.concat([cipher.update(clear, "utf8"), cipher.final()]);
    return Buffer.concat([iv, cipher.getAuthTag(), body]);
}

export function decryptPayload(key: Buffer, stored: Buffer): string {
    const iv = stored.subarray(0, IV_LENGTH);
    const tag = stored.subarray(IV_LENGTH, IV_LENGTH + TAG_LENGTH);
    const body = stored.subarray(IV_LENGTH + TAG_LENGTH);
    const decipher = createDecipheriv(ALGORITHM, key, iv, { authTagLength: TAG_LENGTH });
    decipher.setAuthTag(tag);
    return Buffer.concat([decipher.update(body), decipher.final()]).toString("utf8");
}
```

```ts
import { createHmac, randomUUID, timingSafeEqual } from "node:crypto";
import type {
    IPaymentAdapter,
    IPaymentEvent,
    IPaymentStart,
    IPaymentStarted,
} from "../interfaces/payment-adapter.interface";

export const SIMULATED_PROVIDER = "SIMULATED";
export const SIGNATURE_HEADER = "x-clemperl-signature";

const STATUSES = ["PENDING", "SETTLED", "FAILED"] as const;

export function signSimulatedPayload(secret: string, raw: string): string {
    return createHmac("sha256", secret).update(raw).digest("hex");
}

// Comparaison à temps constant : comparer deux signatures avec `===` laisse mesurer où
// elles divergent, et donc les deviner octet par octet.
//
// Les longueurs se comparent sur les OCTETS et non sur les caractères : `timingSafeEqual`
// lève sur deux tampons de tailles différentes, et une signature de 64 caractères
// multioctets produit plus de 64 octets. Un en-tête fabriqué ferait alors lever une
// fonction dont le contrat est de rendre `null`.
function sameSignature(expected: string, received: string): boolean {
    const a = Buffer.from(expected, "utf8");
    const b = Buffer.from(received, "utf8");
    if (a.length !== b.length) {
        return false;
    }
    return timingSafeEqual(a, b);
}

// Le fournisseur de développement, à la manière de Mailpit pour les courriels. Il n'existe
// que pour exercer le parcours entier, redirection comprise, sans compte chez personne.
export class SimulatedAdapter implements IPaymentAdapter {
    readonly provider = SIMULATED_PROVIDER;

    constructor(
        private readonly secret: string,
        private readonly publicUrl: string,
    ) {}

    async start(input: IPaymentStart): Promise<IPaymentStarted> {
        const providerRef = `sim_${randomUUID()}`;
        const url = new URL(`${this.publicUrl}/payments/simulator/${providerRef}`);
        url.searchParams.set("amount", String(input.amount));
        url.searchParams.set("currency", input.currency);
        url.searchParams.set("reference", input.reference);
        url.searchParams.set("returnUrl", input.returnUrl);
        return { providerRef, redirectUrl: url.toString() };
    }

    interpret(raw: string, headers: Readonly<Record<string, string>>): IPaymentEvent | null {
        const received = headers[SIGNATURE_HEADER];
        if (typeof received !== "string") {
            return null;
        }
        if (!sameSignature(signSimulatedPayload(this.secret, raw), received)) {
            return null;
        }

        let body: unknown;
        try {
            body = JSON.parse(raw);
        } catch {
            return null;
        }
        if (typeof body !== "object" || body === null || Array.isArray(body)) {
            return null;
        }

        const { providerRef, status } = body as { providerRef?: unknown; status?: unknown };
        if (typeof providerRef !== "string" || providerRef === "") {
            return null;
        }
        if (typeof status !== "string" || !STATUSES.includes(status as never)) {
            return null;
        }
        return { providerRef, status: status as IPaymentEvent["status"] };
    }
}
```

```ts
import { E_PAYMENT_METHOD } from "@clemperl/db/enums";
import type { IPaymentAdapter } from "../interfaces/payment-adapter.interface";
import { SimulatedAdapter } from "./simulated.adapter";

export type TPaymentRegistry = ReadonlyMap<string, IPaymentAdapter>;

export interface IRegistryOptions {
    simulator: boolean;
    secret: string;
    publicUrl: string;
}

// Les méthodes qui ONT BESOIN d'un adapter, déclarées une seule fois dans
// `packages/domain` et lues ici comme par les deux fronts. Les autres se règlent hors
// ligne quoi qu'il arrive : un virement n'a pas de redirection à offrir.
//
// Le registre DÉRIVE de cette déclaration au lieu d'en tenir une copie. Sans cela, l'API
// et les écrans tiennent chacun leur liste, et le jour où elles divergent un vendeur coche
// une méthode que la plateforme ne sait pas servir : l'acheteur voit « Payer » et reçoit un
// refus à chaque fois, pendant que l'écran du vendeur lui retire le bouton de pointage.
import { PROVIDER_PAYMENT_METHODS } from "@clemperl/domain";

export function buildRegistry(options: IRegistryOptions): TPaymentRegistry {
    const registry = new Map<string, IPaymentAdapter>();
    if (options.simulator) {
        const adapter = new SimulatedAdapter(options.secret, options.publicUrl);
        for (const method of SIMULATED_METHODS) {
            registry.set(method, adapter);
        }
    }
    return registry;
}

// Une méthode EN LIGNE est une méthode qui a un adapter. Pas de booléen à côté, pas de
// liste à synchroniser, pas de manière d'être incohérent.
export function isOnline(registry: TPaymentRegistry, method: string): boolean {
    return registry.has(method);
}

export function adapterFor(registry: TPaymentRegistry, method: string): IPaymentAdapter | null {
    return registry.get(method) ?? null;
}

export function offlineMethods(registry: TPaymentRegistry): string[] {
    return Object.values(E_PAYMENT_METHOD).filter((method) => !registry.has(method));
}
```

```ts
import type { PrismaClient } from "../client.js";

export const ERROR_PAYMENT_ORDER_NOT_FOUND = "PAYMENT_ORDER_NOT_FOUND";
export const ERROR_PAYMENT_ORDER_CANCELLED = "PAYMENT_ORDER_CANCELLED";
export const ERROR_PAYMENT_ALREADY_SETTLED = "PAYMENT_ALREADY_SETTLED";
export const ERROR_PAYMENT_NOT_OFFLINE = "PAYMENT_NOT_OFFLINE";
export const ERROR_PAYMENT_REF_UNKNOWN = "PAYMENT_REF_UNKNOWN";

// Le filtre par acheteur vit dans la SIGNATURE : `orderId` vient de l'URL, donc du client.
export async function readOrderToPay(
    prisma: PrismaClient,
    input: { buyerId: string; orderId: string },
): Promise<{
    id: string;
    reference: string;
    amount: number;
    currency: string;
    method: string;
}> {
    const order = await prisma.order.findFirst({
        where: { id: input.orderId, buyerId: input.buyerId },
        select: {
            id: true,
            reference: true,
            status: true,
            totalAmount: true,
            currency: true,
            paymentMethod: true,
            paymentStatus: true,
        },
    });
    if (!order) {
        throw new Error(ERROR_PAYMENT_ORDER_NOT_FOUND);
    }
    if (order.status === "CANCELLED") {
        throw new Error(ERROR_PAYMENT_ORDER_CANCELLED);
    }
    if (order.paymentStatus === "SETTLED") {
        throw new Error(ERROR_PAYMENT_ALREADY_SETTLED);
    }
    return {
        id: order.id,
        reference: order.reference,
        amount: order.totalAmount,
        currency: order.currency,
        method: order.paymentMethod,
    };
}

export async function recordAttempt(
    prisma: PrismaClient,
    input: {
        orderId: string;
        method: string;
        amount: number;
        currency: string;
        provider: string;
        providerRef: string;
    },
): Promise<string> {
    const attempt = await prisma.orderPayment.create({
        data: {
            orderId: input.orderId,
            method: input.method as never,
            amount: input.amount,
            currency: input.currency as never,
            provider: input.provider,
            providerRef: input.providerRef,
        },
        select: { id: true },
    });
    return attempt.id;
}

// `changed` à `false` dit un REJEU, et non un échec : le fournisseur rejoue ses webhooks,
// et l'appelant doit lui répondre 200 pour qu'il cesse.
export async function applyProviderEvent(
    prisma: PrismaClient,
    input: {
        provider: string;
        providerRef: string;
        status: "PENDING" | "SETTLED" | "FAILED";
        rawPayload: Buffer;
    },
): Promise<{ changed: boolean }> {
    return prisma.$transaction(async (tx) => {
        const attempt = await tx.orderPayment.findUnique({
            where: {
                provider_providerRef: {
                    provider: input.provider,
                    providerRef: input.providerRef,
                },
            },
            select: { id: true, status: true, orderId: true },
        });
        // Si Prisma refuse `findUnique` sur une clé composée de colonnes nullables, passer
        // à `findFirst` avec les deux égalités : la contrainte d'unicité reste la garantie,
        // c'est seulement le type généré qui change.
        if (!attempt) {
            throw new Error(ERROR_PAYMENT_REF_UNKNOWN);
        }

        // Une tentative déjà tranchée ne se rouvre pas. C'est ce qui rend le rejeu sans
        // effet, et ce qui empêche un événement tardif d'annuler une issue plus récente.
        // Ce chemin court sert le rejeu SÉQUENTIEL ; la garde de l'écriture ci-dessous
        // tient le rejeu CONCURRENT, où deux livraisons lisent toutes deux `PENDING`.
        if (attempt.status !== "PENDING") {
            return { changed: false };
        }

        // `updateMany` avec le statut dans le `where`, comme `setOrderStatus` : sans cette
        // condition, deux livraisons simultanées réécrivent chacune la tentative et
        // annoncent toutes deux un changement.
        const moved = await tx.orderPayment.updateMany({
            where: { id: attempt.id, status: "PENDING" },
            data: {
                status: input.status as never,
                rawPayload: input.rawPayload,
                settledAt: input.status === "SETTLED" ? new Date() : null,
            },
        });
        if (moved.count === 0) {
            return { changed: false };
        }

        // Un événement en attente dit où en est le FOURNISSEUR, pas où en est l'argent :
        // il se garde sans rien affirmer.
        //
        // `not: "SETTLED"` ferme le cas des deux onglets : deux tentatives naissent, l'une
        // règle la commande, et l'échec tardif de l'autre ne doit pas la rouvrir. La
        // tentative garde son échec, la commande garde son règlement.
        if (input.status !== "PENDING") {
            await tx.order.updateMany({
                where: { id: attempt.orderId, paymentStatus: { not: "SETTLED" } },
                data: { paymentStatus: input.status as never },
            });
        }
        return { changed: true };
    });
}

// `offlineMethods` vient de l'appelant : ce paquet ne connaît pas le registre des adapters,
// qui vit dans l'API, et ne peut pas l'importer.
export async function settleOffline(
    prisma: PrismaClient,
    input: {
        vendorId: string;
        orderId: string;
        userId: string;
        offlineMethods: readonly string[];
    },
): Promise<void> {
    await prisma.$transaction(async (tx) => {
        const order = await tx.order.findFirst({
            where: { id: input.orderId, vendorId: input.vendorId },
            select: {
                id: true,
                totalAmount: true,
                currency: true,
                paymentMethod: true,
                paymentStatus: true,
            },
        });
        if (!order) {
            throw new Error(ERROR_PAYMENT_ORDER_NOT_FOUND);
        }
        if (!input.offlineMethods.includes(order.paymentMethod)) {
            throw new Error(ERROR_PAYMENT_NOT_OFFLINE);
        }
        if (order.paymentStatus === "SETTLED") {
            throw new Error(ERROR_PAYMENT_ALREADY_SETTLED);
        }

        // La COMMANDE d'abord, sous garde, et la tentative seulement ensuite. Une
        // tentative hors ligne n'a ni fournisseur ni référence, donc aucune contrainte
        // d'unicité ne l'arrête : sans cette garde, un double clic crée deux lignes
        // réglées pour un seul encaissement.
        const settled = await tx.order.updateMany({
            where: { id: order.id, paymentStatus: { not: "SETTLED" } },
            data: { paymentStatus: "SETTLED" },
        });
        if (settled.count === 0) {
            throw new Error(ERROR_PAYMENT_ALREADY_SETTLED);
        }

        await tx.orderPayment.create({
            data: {
                orderId: order.id,
                method: order.paymentMethod,
                status: "SETTLED",
                amount: order.totalAmount,
                currency: order.currency,
                settledById: input.userId,
                settledAt: new Date(),
            },
        });
    });
}
```

```ts
import {
    ForbiddenException,
    Inject,
    Injectable,
    type CanActivate,
    type ExecutionContext,
} from "@nestjs/common";

export const ALLOWED_ORIGINS = Symbol("CLEMPERL_ALLOWED_ORIGINS");

// La comparaison est une ÉGALITÉ sur l'origine entière, jamais un préfixe :
// `http://localhost:3000.ailleurs.test` commence comme une origine connue.
@Injectable()
export class OriginGuard implements CanActivate {
    constructor(@Inject(ALLOWED_ORIGINS) private readonly allowed: readonly string[]) {}

    canActivate(context: ExecutionContext): boolean {
        const request = context.switchToHttp().getRequest<{
            headers: Record<string, string | undefined>;
        }>();
        const origin = request.headers["origin"];
        if (typeof origin !== "string" || !this.allowed.includes(origin)) {
            throw new ForbiddenException("Origine absente ou refusée.");
        }
        return true;
    }
}
```

```ts
import {
    applyProviderEvent,
    prisma,
    readOrderToPay,
    readVendorForMember,
    recordAttempt,
    settleOffline,
} from "@clemperl/db";
import { Inject, Injectable, NotFoundException } from "@nestjs/common";
import { adapterFor, offlineMethods, type TPaymentRegistry } from "../adapters/registry";
import { encryptPayload } from "../utils";
import { PAYMENTS_ENV, PAYMENT_REGISTRY } from "../constants";
import type { IPaymentsEnv } from "../interfaces";

export const ERROR_NO_ADAPTER = "PAYMENT_NO_ADAPTER";
export const ERROR_NOT_A_MEMBER = "PAYMENT_NOT_A_MEMBER";

@Injectable()
export class PaymentsService {
    constructor(
        @Inject(PAYMENT_REGISTRY) private readonly registry: TPaymentRegistry,
        @Inject(PAYMENTS_ENV) private readonly env: IPaymentsEnv,
    ) {}

    async start(input: { buyerId: string; orderId: string; locale: string }): Promise<string> {
        const order = await readOrderToPay(prisma, {
            buyerId: input.buyerId,
            orderId: input.orderId,
        });

        const adapter = adapterFor(this.registry, order.method);
        if (adapter === null) {
            throw new Error(ERROR_NO_ADAPTER);
        }

        const started = await adapter.start({
            orderId: order.id,
            reference: order.reference,
            amount: order.amount,
            currency: order.currency,
            returnUrl: `${this.env.storefrontUrl}/${input.locale}/orders/${order.reference}`,
        });

        // La tentative est écrite AVANT de rendre l'URL. Dans l'autre ordre, un webhook
        // rapide arriverait sur une référence que la base ne connaît pas encore, et serait
        // refusé alors que le paiement a bien eu lieu.
        await recordAttempt(prisma, {
            orderId: order.id,
            method: order.method,
            amount: order.amount,
            currency: order.currency,
            provider: adapter.provider,
            providerRef: started.providerRef,
        });

        return started.redirectUrl;
    }

    async settle(input: { userId: string; orderId: string }): Promise<void> {
        const vendor = await readVendorForMember(prisma, input.userId);
        if (!vendor) {
            throw new Error(ERROR_NOT_A_MEMBER);
        }
        await settleOffline(prisma, {
            vendorId: vendor.id,
            orderId: input.orderId,
            userId: input.userId,
            offlineMethods: offlineMethods(this.registry),
        });
    }

    // Rend `false` quand la signature est fausse ou le corps illisible, pour que le
    // contrôleur réponde 400 sans rien écrire.
    async receive(input: {
        provider: string;
        raw: string;
        headers: Readonly<Record<string, string>>;
    }): Promise<boolean> {
        const adapter = [...this.registry.values()].find((a) => a.provider === input.provider);
        if (!adapter) {
            throw new NotFoundException("Fournisseur inconnu.");
        }

        const event = adapter.interpret(input.raw, input.headers);
        if (event === null) {
            return false;
        }

        // Le payload est chiffré ICI, tel qu'il a été reçu, avant toute interprétation de
        // son contenu.
        await applyProviderEvent(prisma, {
            provider: adapter.provider,
            providerRef: event.providerRef,
            status: event.status,
            rawPayload: encryptPayload(this.env.payloadKey, input.raw),
        });
        return true;
    }
}
```

`GET /:ref` rend une page HTML minuscule : le montant formaté, la référence de la commande,
et deux formulaires qui postent sur la même URL avec un champ caché `outcome` valant
`SETTLED` ou `FAILED`, plus `returnUrl`.

**Cette page est servie depuis l'origine de l'API et renvoie des paramètres d'URL dans son
HTML.** Tout paramètre réaffiché doit donc être échappé, sinon la page est une faille de
script injecté réfléchi. Valider aussi `amount`, `currency` et `outcome` plutôt que de les
réafficher tels quels.

`POST /:ref` fait trois choses, dans cet ordre :

1. **Vérifie que `returnUrl` commence par `env.storefrontUrl` suivi de `/`.** Sinon,
   `BadRequestException`. Sans cette vérification, la page est une redirection ouverte : une
   URL fabriquée enverrait l'acheteur ailleurs depuis un domaine qu'il croit être le nôtre.
2. **Appelle son PROPRE webhook** sur `http://127.0.0.1:3003/payments/webhook/SIMULATED`,
   avec le corps `{ providerRef, status }` signé par `signSimulatedPayload`. Le détour est
   délibéré : marquer le paiement directement serait plus court et n'exercerait ni la
   signature, ni la normalisation, ni l'idempotence, c'est-à-dire les trois choses qu'un vrai
   fournisseur mettra à l'épreuve.
3. **Redirige en 303** vers `returnUrl`. 303 et non 302 : la redirection suit un POST, et 303
   est ce qui dit au navigateur de la suivre en GET.

```tsx
import { useState } from "react";

interface IProps {
    orderId: string;
    locale: string;
    apiUrl: string;
    // Les libellés arrivent en PROPS, traduits par le composant serveur. Les traduire ici
    // tirerait `@clemperl/core` dans le paquet du navigateur, donc nodemailer, donc
    // `node:net`.

}

export function PayButton({ orderId, locale, apiUrl, labels }: IProps) {
    const [busy, setBusy] = useState(false);
    const [failed, setFailed] = useState(false);

    async function pay(): Promise<void> {
        setBusy(true);
        setFailed(false);
        try {
            // `credentials: "include"` : sans lui le cookie de session ne part pas vers une
            // autre origine, et l'API répond 401 sans que rien ne l'explique.

                credentials: "include",

                setFailed(true);
                setBusy(false);
                return;
            }
            const { redirectUrl } = (await response.json()) as { redirectUrl: string };
            // `assign` et non le routeur : la destination est le FOURNISSEUR, qui est hors
            // de cette application.
            window.location.assign(redirectUrl);
        } catch {
            setFailed(true);
            setBusy(false);
        }
    }

    return (
        <div className="flex flex-col gap-2">
            <button type="button" onClick={() => void pay()} disabled={busy}>
                {labels.pay}
            </button>
            {failed ? <p role="alert">{labels.failed}</p> : null}
```

- [ ] **Step 3: Écrire l'interrogation**

`payment-watch.tsx`. Elle n'interroge QUE lorsqu'un fournisseur a été sollicité et n'a pas
encore répondu : un paiement à la livraison reste en attente des jours durant, et rafraîchir
sa page toutes les cinq secondes n'apprendrait rien à personne.

```tsx
"use client";

import { useRouter } from "next/navigation";
import { useEffect } from "react";

const INTERVAL_MS = 5000;
// Cinq minutes. Au-delà, un onglet oublié rafraîchirait une page que personne ne lit.
const MAX_TICKS = 60;

export function PaymentWatch({ awaiting }: { awaiting: boolean }) {
    const router = useRouter();

    useEffect(() => {
        if (!awaiting) {
            return;
        }
        let ticks = 0;
        const timer = setInterval(() => {
            ticks += 1;
            if (ticks > MAX_TICKS) {
                clearInterval(timer);
                return;
            }
            router.refresh();
        }, INTERVAL_MS);
        return () => clearInterval(timer);
    }, [awaiting, router]);

    return null;
}
```

- [ ] **Step 8: Un seul commit**

Un commit unique pour toute la tranche, en anglais, COURT : chaque PR est fusionnée en squash,
et un long empilement de messages ne sera jamais relu. La spec et ce plan y voyagent.

```bash
git switch -c feat/payments
git add -A
git commit
```

Le corps tient en quelques lignes : ce qui change, et ce qui ne se lit pas dans le diff
(l'axe séparé, la décision de ne rien fermer, le simulateur à la place d'un vrai fournisseur).

- [ ] **Step 9: Ouvrir la PR et demander la revue**

```bash
git push -u origin feat/payments
gh pr create --fill
```

La PR doit rester **sous 100 fichiers**, limite du forfait CodeRabbit, et son corps sous
1500 caractères (`wc -m`). CodeRabbit ne relit pas ce dépôt automatiquement, qui a moins de
dix étoiles : commenter `@coderabbitai review` sur la PR, sans quoi personne ne la relit.

La CI ne se déclenche que sur `pull_request` et sur les poussées vers `main` : une branche
poussée seule n'est vérifiée par rien, et c'est l'ouverture de la PR qui tranche.
